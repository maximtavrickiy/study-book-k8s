# 04 ArgoCD / GitOps — практика

Исходная точка: рабочий кластер, снапшот `03-cni-final`.

## Установка

- [ ] Выбрать способ: аддон Kubespray (`argocd_enabled` в group_vars, проверить для своей версии) или вручную манифестом/Helm; записать выбор и почему
- [ ] **На mgmt:** установить ArgoCD, дождаться, что все поды в `argocd` Running
- [ ] Получить начальный пароль admin (**не коммитить**), сменить его
- [ ] Открыть UI через `kubectl port-forward` или NodePort с хоста
- [ ] Установить CLI `argocd` на mgmt и залогиниться
- [ ] 📸 **Снапшот: `04-argocd-installed`**

## Репозиторий манифестов

- [ ] Создать в своём GitLab репозиторий манифестов (например `k8s-lab-manifests`)
- [ ] Положить туда Deployment + Service простого приложения
- [ ] Подключить репозиторий к ArgoCD (deploy token или SSH-ключ только на чтение; **токен не коммитить**)
- [ ] Создать `Application` декларативно (YAML), сохранить его в `artifacts/`
- [ ] Выполнить Sync, проверить приложение в кластере

## Эксперименты

- [ ] Изменить число реплик в Git → наблюдать синхронизацию
- [ ] Вручную изменить объект в кластере (`kubectl scale` / `edit`) без self-heal → увидеть OutOfSync
- [ ] Включить `selfHeal` → повторить и наблюдать откат изменения
- [ ] Удалить манифест из Git с `prune` и без него → сравнить поведение
- [ ] Закоммитить сломанный манифест (ошибка YAML / несуществующий образ) → что показывает ArgoCD и что происходит с работающим приложением
- [ ] (Опционально) App of Apps для нескольких приложений
- [ ] 📸 **Снапшот: `04-gitops-done`**
